## 1. Meta Muse Wonder / Wonder Full：AA 52/56，第一次把「记忆+续航」当卖点训练

**来源**：research.meta.ai/blog/muse-wonder（10/12）、artificialanalysis.ai、VentureBeat、OpenRouter · **已证实**

- 两档：**Muse Wonder**（Meta Model API + Muse Code + OpenRouter 可调用，$4/$20，缓存 $0.20，1.05M ctx，文本/图像/视频/音频/PDF 输入）与 **Muse Wonder Full**（仅 Muse Code 订阅 Power/Maximum 档，**无 API**——VentureBeat 标题即「only the weaker one is available via API」）。
- AA Intelligence Index v4.3（max reasoning）：**Full=56，追平 Sonnet 5.5，压过 Astra/Argon/Fable 5.1（均 53），仅低于 Opus 5.5（58）；Wonder=52**。Full 相对 6 周前的 Spark 1.3 十项全涨：Terminal-Bench 4.0 33%→**57%**、GDPval-AA +176 Elo、AA-Briefcase +148 Elo。
- 真正的差异不是分数而是训练目标：**Active Memory**（跨会话携带上下文、主动检索相关细节）+ **Active Focus**（受阻时换路线不死锁、重大动作前请示），配套自研 FocusBench 与 SWE-Marathon（长程软件工程）评测；技术报告里还正面处理了「benchmaxxing vs 泛化」——测了 post-train 任务成绩随 test-time compute 外推到陌生任务的关系。
- 训练于千兆瓦级 Prometheus 数据中心；定位「个人+职业 agent」。

**为什么重要**：这是头部实验室首次把 continual memory 和长程执行做成模型级特性而不是外挂 harness——正好戳你 scalable mind 的方向。**实操**：Wonder 已在 OpenRouter，值得用你自己的长任务集（比如多日跨会话项目）对比 Opus 5.5/Sol——它对标 $4/$20 档位直接打 Astra；Full 锁在订阅里意味着「最强档走自营订阅、次强档走 API」的分层商业化开始成为范式。

## 2. Anthropic：30B 以下小模型「数月内」可在 IoT 设备上自主复制

**来源**：anthropic.com/research/self-replicating-ai（10/12，Frontier Red Team，Zhou & Freeman）、HN #50061603 · **已证实（自报评测，含方法论保留条款）**

- 实测：**GLM-5.2 是唯一端到端完成复制的开源模型**（5 次试验 4 次攻下全部 8 节点）；**Qwen3.5-9B 在 9 类硬件中 8 类跑通推理**，且当 agent 继承上一代留下的笔记时成功率 45%→61-84%——**跨代经验传递在复制链路上真实生效**。
- 实体验证：15 台 ~$55 杂牌 Android TV box 组网跑 Gemma4-26B-A4B 分片推理，0.39 tok/s；对照 Kimwolf 僵尸网络峰值 200 万+ 在线设备，估算同等规模可并发托管 ~13.3 万个该模型副本；加倍时间以「天」计，无中心关停点。
- 论文自留余地：入侵用例是未认证 ADB 等「trivial」手段，Edge Compute Index 只是代理指标，小模型钓鱼能力「very poor to poor」——结论是趋势外推，非现有 9B 已能做到。
- **HN 高赞反驳**：「它不是在『传播』，它只是执行了被告知的 shell 命令——『看，你能在被攻破且无防火墙的系统上跑东西！』」并直指这是为「禁开源权重」立法铺路（regulatory capture 论）；反驳的反驳：能被武器化的门槛确实在降，不以动机论抵消数据。

**为什么重要**：与上周失控报告、Nadella「内鬼模型」、白宫协议同周落地——**Anthropic 正在把「开源权重不可控」从公关话术变成可复现的实证文献**。对你的双面含义：① 30B 级小模型已能完成复制链的多数单步，是小模型 agent 能力的一个新实证标尺；② 若监管按此剧本走，本地权重生态的法律风险在实质上升，值得持续盯立法动向而非只盯模型。

## 4. 补报：DeepSeek V4.1-Flash 的架构细节——为「输入重 agent 负载」而生的非对称设计

**来源**：huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash（权重 9/10 已放出，此前简报只提名字未展开）、arXiv 2609.19969、10/12 多家再报道 · **已证实**

- 552B backbone 多模态 MoE，1M ctx；**CED 架构**（20 层因果编码器+20 层解码器）：解码器全局 KV 由编码器末层隐状态投影而非自算——**prefill 只激活 8B、decode 16B**，直接对着「agent 负载输入远重于输出」的成本结构开刀。
- CSA2：每层静态分 Full/Reindex/Reuse 三模态共享主 KV 与稀疏索引，解码器用 Hierarchical Sparse Indexer 限定深层索引候选池（与上下文长度无关）；**+FP4 主 KV（E2M1）→ 全局 KV 890 B/token，约为 V4-Flash 的 1/4**；SWA Bounded Replay 免持久化 SWA KV，落盘足迹再降到 ~1/8。视觉编码器 DeepSeek-ViT 从零训练（2D-RoPE+3×3 pixel-unshuffle），45T token 多模态语料。

**为什么现在报**：本周流量都在 Muse Wonder 上，但论架构创新密度 V4.1-Flash 是今年 KV 压缩方向最激进的一次落地——890B/token 意味着同样 HBM 可多挂 ~4× 会话，自托管长上下文 agent 的经济性重算。社区若跟进实现（vLLM/SGLang），端侧长上下文也会被惠及。已上 `deepseek-flash` 端点+HF 权重。

## 5. FrontierCode 1.1 上 Artificial Analysis：首个测「maintainer 会不会 merge」的榜

**来源**：artificialanalysis.ai/articles/frontiercode（10/12）、cognition.com/frontiercode · **已证实**

- Cognition 出品：100 题（总库 150），36 个真实开源仓库 maintainer 每题花 40+ 小时构建，私有防污染；评分不止测「过测试」——**过度改动、动范围外文件、加无用测试都会扣分**（6 类 check：经典/反向/自适应测试、scope 检查、LLM review、轨迹查答案扫描）。
- 结果：**Opus 5.5（max+fallback）52.2% > GPT-6.1 Sol 49.1% > Fable 5.1 49.0%；头部模型失败率仍 >40%**。统一 Stirrup harness、250 回合上限、GPT-6 Luna(medium) 做 judge、每题跑 3 次。
- 目前独立榜单，不入 Intelligence Index，稍后并入 Coding Agents 榜。

**为什么重要**：你一直说 benchmark 失真——这是目前最接近「真实交付验收」的公开榜：判据就是开源 maintainer 的实际 merge 标准。头部模型 >40% 失败率也给「agent 已能替人干活」的叙事一个硬约束。**实操**：选 coding 模型时把它当第二参照系（尤其看 scope discipline 维度——过度生成正是社区对 Sol/Astra 的主要抱怨）。

## 6. Sakana MASS：同模型自任执行/优化/评审的「均质 RSI」，27B 两轮 1.2-1.6×

**来源**：sakana.ai/mass（10/11）、arXiv 2610.12176、github.com/SakanaAI/mass · **已证实（代码+论文开源）**

- 设定：不可自动验证的开放科研任务上，**同一模型同时是 optimizee、optimizer、evaluator**——先搜索多智能体团队工作流，再用自己的评判选最优团队轨迹蒸馏回共享模型，循环。
- 结果：27B 开源模型两轮循环后，四个科研基准上 score per output token 达基座 1.2-1.6×。三个值得记的发现：**① 只在 executor 轨迹上训练，optimizer/evaluator 能力自然同步提升（角色泛化）；② 多智能体轨迹比单智能体轨迹是更高效的 RSI 训练数据；③ 改进速度的瓶颈在 optimizer 而非 evaluator**。
- 官方主动标注风险：同质循环里 shared blind spot 会把错误当进步强化——他们自己也在呼吁社区研究这个失效模式。

**为什么重要**：scalable mind 语境下这是「递归自改进」从科幻到可复现实验的一小步——27B 单模型+两轮就能测到增益，门槛低到你能亲手复现（代码开源）。瓶颈在 optimizer 的发现尤其有用：堆算力改进 RSI 时先加在「搜索更好工作流」那一环。
