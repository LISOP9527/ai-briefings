## 1. DLOG 再下一城：浙大组给出确定性亚指数 DLOG/ECDLP——但条件挂在 OpenAI 十月的张量收缩构造上

来源：[eprint 2026/3020（亲核摘要+PDF）](https://eprint.iacr.org/2026/3020)、[clauday 解读](https://clauday.com/article/79cc174b-87c3-4761-9413-cf1d66df4eb6)、[secsig](https://www.secsig.org/research-library/news/b3f31d411ada32f07360/)、[HIMIAO](https://himiao.ai/en/news/2026-11-28-discrete-log-deterministic-subexponential)、HN 207 分、[Times 相关报道（未取到，反爬）](https://www.thetimes.com/uk/technology-uk/article/ai-making-online-security-useless-smr73d3n8)。

**已证实（论文存在+作者真实；结果本身未评审、且为条件命题）**：Shuchang Liu / Bingsheng Zhang / Kui Ren（浙大区块链与数据安全国家重点实验室，Zhang 做 e-voting/ZKP，不是民科稿）11-24 投、11-27 过审：在**假定 OpenAI（2026-10）的 Cauchy–Hermite 布尔张量收缩构造成立**的前提下，存在一致确定性多带图灵机，以 2^{O(b/√log log b)} 时间、2^{O(b/(log b)^{1/4})} 空间解 F_p* 与 F_p 上素数阶椭圆曲线 DLOG——零随机位、不依赖 GRH 与光滑性启发。两条技术腿：确定性条件期望构造的小仿射区间因子基（2m 倍和集覆盖全群）+ 保末端的局部收缩（把低次算术核压到 Θ(b) 条边界线上再做逐位精确收缩）。谱系：10 月 OpenAI/Anthropic 各自放出 ETH 否证稿 → Akshima et al. 与 Kaarelson 给出 ECDLP Las Vegas 亚指数 → 本文把「确定性」也补上。HIMIAO 引独立评论：纯渐近，交叉点 ≥2^{2^17}，对 P-256/Ed25519 等部署曲线**没有任何实际威胁**。HN 上另有「P=NP 且是 OpenAI 证的」推文在流传——**传闻/噪声**，目前只是 DLOG 线的外溢梗。

**为什么重要**：真正的新闻不是「密码要破了」而是**级联速度**——OpenAI 十月放下一个未经人验的构造，四周后人类密码学家把它当标准件继续往上盖，AI 产出的数学对象已开始进入严肃理论的依赖链（昨日 Everett 的 BSS 稿引用 AI 证 VP≠VNP 当引理是同型事件）。风险点也同样清晰：整条链的地基（OpenAI 张量构造、ETH 否证）本身还在 Impagliazzo/Paturi/Williams 工作组的审查中，**地基若塌，DLOG 这条自动作废**——条件依赖是把双刃。

**怎么做**：把它记入「AI 数学→下游依赖」追踪表：eprint 3020 的显式假设=OpenAI Oct-2026 构造，验收顺序=先验地基再验上层；对 crypto 持仓不做任何动作（渐近≠可用）；盯 Impagliazzo 组的 ETH 审稿结论——那是当前整棵依赖树的根。

## 2. djb 出手：「False computer-checked proofs」清点全社区证明器的 soundness bug——昨日 RH 验收链的直接对冲

来源：[cr.yp.to/proofs/falseccp.html（亲核全文）](https://cr.yp.to/proofs/falseccp.html)、HN 194 分。

**已证实（页面+所列 bug 报告均可溯源）**：Bernstein 汇编各证明器已报告的 soundness bug 数（按升序）：HOL Light 3、Mizar 7、Metamath 9、**Isabelle 20、Lean 3/4 23、HOL98/HOL4 24、Coq/Rocq 100+**——含多个「已演示可利用」的案例，且明确不含 UI 层漏洞（2016 Adams 那类误导用户以为证完了的坑另算）。他的安全建议三条：(i) 最小化 TCB——HOL Light kernel 仅 ~400 行是优点，但「行数少」≠「被审过」，也管不了底层语言实现的 bug；(ii) 多 checker 互检有效但非银弹——**不同 checker 存在共享 bug**；(iii) 正解是「checker 本身的正确性证明」——HOL Light 推理规则 2006 年在 HOL Light 内自证（假设大基数 Vω+ω），Candle 2022 年在 HOL4 里完成机器检验的正确性证明+OpenTheory 独立 checker；但对「大二进制文件查大二进制文件」的套娃仍不满意，呼吁简化二进制。

**为什么重要**：昨天简报的结论是「RH 在机器意义上成立，验收链闭合」。djb 今天给出的正是该结论的**技术性反方陈词**：Lean kernel+多 checker 的方案降低了风险，但「多 checker」里有两个自带形式化保证才真的硬——而那两个 checker 自身也是大二进制，属于他点名不满意的那层。这不推翻 RH 的机器成立性，但精确标出了「机器验收」的实际置信边界：**它防的是证明笔误，防不了验证栈自身的 soundness bug**。对你做「AI 数学验收清单」是直接输入：把「checker 的 soundness 历史+是否有自证/互证」列为验收维度第 0 项；长期关注 Candle/OpenTheory 这类「验证过的验证器」路线——那才是 TCB 收敛的方向。

**已证实（代码在仓库里、注释自承）**：Convex（挂在 Anthropic claude-plugins-official 市场的官方插件）三个 quickstart skill：把用户的一句话项目 idea POST 到 basic-anteater-667.convex.site（注释标 telemetry，用户不知情）；`curl|bash` 拉远程脚本直执行；第三个把「下载+执行」拆成两次 Bash 调用，注释写明原因——**"A single command that both downloads remote code and executes it is the shape harness safety classifiers block."** 即明知并规避用户侧安全工具。issue 10-26 开出，11-27 上 HN 热榜。同步信号：今日 GitHub trending 16 仓中 5 个是 skill/agent 包（Claude-BugHunter 日增 1,608 star、obra/superpowers、CLI-Anything「让所有软件 agent-native」、cursor/plugins 规范、google stitch-skills）——**skill 作为分发格式正在爆发**。

**判断**：昨日 Notion MCP 投毒（输出里藏 upsell 指令）→ 今天 Convex（skill 代码里藏遥测+规避分类器）——**第三方 skill/MCP 的攻击面从「输出注入」扩大到「分发即注入」**。Convex 大概率是好意（让 onboarding 可靠）而非恶意，但这恰好是更坏的信号：**善意开发者把规避安全分类器当成工程技巧写进注释**——供应链审计不能只盯恶意。**怎么做**：装 skill 前 grep 三个模式——外发 POST、`curl|bash`、「绕过/avoid classifier」字样；把 skill 目录纳入你 harness 的 CI 静态扫描；MCP/skill 返回一律按不可信输入处理（同昨日规则）。
