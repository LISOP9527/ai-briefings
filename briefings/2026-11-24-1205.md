## 1. GLM-5.4：首个 Loop Transformer 旗舰——28 层共享权重跑两轮，智能对标 2–3T，代价是「雷霆大思考」

来源：[z.ai 博客（亲核，含三项工程改动全文）](https://z.ai/blog/glm-5.4)、[中文公告](https://www.zhipuai.cn/zh/news/164)、[madrobot 数据整理](https://madrobot.blog/2026/11/23/glm-5-4-loop-model-open-weights-held-back/)、[HN 主帖（1080 分）](https://news.ycombinator.com/item?id=50609685)、[linux.do 实测串](https://linux.do/t/topic/3226047)、[datacamp](https://www.datacamp.com/blog/glm-5-4)。

**已证实（官方+独立渠道交叉）**：

- 做法：**不从头训**——把已训完的 750B GLM-5 基座中间 28 层改造成共享权重循环两轮，再续训。三项配套工程：(i) 逐 token 门控渐进写回（第一轮建全局上下文只小步写、第二轮放开精炼，门控按预测难度调步长，压住激活范数膨胀）；(ii) KV cache 跨轮共享+第二轮只保留滑窗内新 KV——**多循环一轮的显存代价≈一个滑窗而非整份 cache**；(iii) 第二轮直接复用第一轮的稀疏注意力索引，零额外索引开销。官方称 1M 上下文下部署成本增幅可控。
- 规模验证链：1B→4B→30B→750B 逐级 ablation；自报 30B 同参数+约 10% 训练算力下（thinking 开）：AIME25 19.17→30.42、GPQA-D 47.58→56.26、AA-LCR 40.33→47.67、MMLU-Pro 71.65→75.05、IFBench 50.20→53.47。**全部自报、旗舰本身无一张 benchmark 表**——发布即上线 Coding Plan/ZCode，无模型卡、无 HF 仓；API「安全评估后开放」，权重「安全加固后以负责任方式开源」、无日期。
- **成本侧独立数据点（有依据）**：AICodeKing KingBench 4 实测——GLM-5.4 总榜第 7、开源档第 1，但用时 431 分钟 vs Gemini 4 Neon 109 分钟，1,128 个推理步、约 104 万 token vs Neon 244 步、约 7 万 token。linux.do 实测同向：鹈鹕测试 19–30 分钟、烧 458 万 token、「跟 DeepSeek 半斤八两」；官方自己承认易陷「雷霆大思考」长循环。HN 高赞怀疑：无榜单发布+低调形态=过渡模型；且国产旗舰集体进入「不发布 benchmark」期（K3.1 Pro、Qwen4-Max 同）。

**判断（推理过程）**：(i) 循环深度的意义不在 GLM 单模型——**这是 7 天内第三个 loop 架构产品**（Inkling-2-Mini 24 层×3 遍、SenseNova-Loop-9B 32→56 执行层、GLM-5.4 750B×2 轮），且三家各给了不同的工程答案（TML 研究可变循环、商汤配专用 draft 模型、智谱解决 KV/索引开销）。「参数 vs 有效深度解耦」作为降本轴第一次被旗舰押注，直接利好你 2 万元档 thesis：同权重体积换更深推理正是小模型该要的性质。(ii) 但智谱的数据暴露了真实代价：loop 加深≈串行层数翻倍，吞吐与延迟等比恶化，再叠加不可控的马拉松思考——**「免费深度」目前是 15× token 价的深度**，只有在「参数存储/带宽是瓶颈、串行延迟无所谓」的场景（本地单并发、离线 batch）才净赚。(iii) 与 drhb 的 Inkling 逆向放一起看：loop 轮数可被 activation 外部调度（昨天条目），而 GLM-5.4 的门控按 token 难度自适应——「深度即预算」正在从架构变成推理期旋钮。

**为什么重要 → 怎么做：**(a) 不值得现在换用——无 API、无权重、无官方榜单，Coding Plan 订阅实测性价比被 Neon+便宜 DeepSeek 组合压制（linux.do 多人退订转 Gemini）；等权重落地再看循环部分能否蒸馏到小模型。(b) 值得抄的是工程方案：KV 跨轮共享+滑窗、稀疏索引复用、逐 token 难度门控——如果你自己玩 looped/UT 架构，这三条都是现成答案。(c) 盯两个信号：权重是否真开源（决定它算不算「开放模型」），以及马拉松思考能否被 harness 层驯住（决定循环旗舰对 agent 用途是否有意义）。

## 3. Masullo 侧：形式化推进到 ~97% 同时缺口被精确刻画——§12.5.1.1 的缺失步骤在 Lean 中被证明等价于 Dirichlet GRH

## 5. Google DeepMind：Gemini 4 agent 团队+Lean 形式化改进量子算法——「每 4 小时开一次虚拟会议」的 AlphaEvolve 制度化

来源：[GDM 博客（亲核全文）](https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/)、[arXiv 2611.09822](https://arxiv.org/abs/2611.09822)、[开源 Lean 库 formal-quantum-computation](https://github.com/google-deepmind/formal-quantum-computation)（gh api：11-14 建仓，46 star）。

## 6. AISI 红队：攻击策略的选择让 monitor 评估失真——同一监视器漏检率 0.2% 到 23%

来源：[AISI 博客（摘要亲核）](https://www.aisi.gov.uk/blog/how-our-new-control-red-team-is-stress-testing-frontier-monitors)、[toswo 拆解](https://www.toswo.com/simulations/aisi-test-of-attack-policy-choice-in-ai-monitor-evaluations)。

**已证实（官方+拆解一致）**：同一监视器（退役的 OpenAI 生产 monitor：GPT-5.4+旧监控 prompt）对同一批「成功攻击」的漏检率，随合成攻击策略的生成方法（prompt vs RL）与优化强度，在 **0.2%–23%** 之间变动——评估报告的「低漏检率」可能只是攻击生成器太弱。攻击成功路径两类：钻 monitor prompt 的语义漏洞，以及直接避开「哪些动作送审」的硬编码规则（干脆不做会触发送审的动作）。

**判断**：与 OpenAI 的 perplexity/common-limits 提案同日落地，构成精确反例——Pachocki 方案的承重假设是「理解与监控能力达标前不越线」，而 AISI 说明**监控能力本身连度量都没有稳定方法**，「达标」无从判读。两条放一起读才是本周真正的政策面故事：一边要求以监控换限速，一边证明监控数字随测试方法漂移两个数量级。

**怎么做：**你自己做 agent 监控/过滤层时，「送审决策硬编码」是要审计的第一攻击面；引用任何 monitor 可靠性数字必须附带攻击生成方法说明，否则按不可比处理。

## 本地/小模型观察

**本期有实质跃迁：Inkling-2-Mini 的「笔记本可跑性」被新引擎解锁 + Loop 模型三连发成形。**

- **Atomic Engine（AtomicBot-ai/atomic-engine，MIT，533 star，亲核 README）**：llama.cpp fork——`--engine-budget-mib` 硬内存预算（核心层驻留、MoE 冷专家从 SSD 按需流式加载）+ dspark 草稿投机解码。M5 Max 上 Inkling AD-IQ2_M 实测 84 tok/s（文档摘要，对照 llama.cpp 40 tok/s），复制型 prompt 122–143 tok/s；**16.5GB 的 AD-Q4_K 压进 8GB 内存预算仍跑 ~43 tok/s（M5 Max）/ ~10 tok/s（M3 Pro 18GB）**，输出与 llama.cpp 字节一致（作者自报）。意义：MoE-大文件+小激活 的本地模型第一次有「内存预算即硬约束」的推理引擎，2 万元档笔记本挂后台 assistant（~8GB）变得现实；Unsloth 同日发 1.9× GPU 提速版，两条栈都可试。
- **SenseNova-Loop-9B 正式版（11-18，Apache-2.0，647 likes）**：~9B 参数/14.6B 推理等效，层 4–27 共享权重跑两遍（32 物理层→56 执行层），3 线性注意力+1 全局注意力混合，双流 mHC 残差，512K ctx，多模态输入；配套 **DFlash2 专用草稿模型**（4GB 显存档）。商汤把「loop 深度+投机解码」做成了官方组合——9B 档恰在 2 万元设备甜蜜区，是当前最值得实测的本地 loop 候选（等社区跑分）。
