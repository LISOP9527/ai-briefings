## 2. 形式化验证出现规模化实例：把现有 fuzz test 变成“所有输入都通过”的证明目标

来源：[Anthropic × Theorem 原文，10/22](https://www.anthropic.com/research/formal-verification)、[公开证明](https://github.com/theorem-labs/oss-verify-proofs)、[机器/OS 语义](https://github.com/theorem-labs/rocq-linux-process-semantics)。
**已证实：研究与公开产物；有依据：规模与效果，来自作者报告。**

- 流程：把库和既有 OSS-Fuzz 入口编译成 RISC-V 二进制 → 机械生成“不崩溃/断言不失败”的规格 → Claude 写 Rocq 证明 → 外部内核检查。作者报告完成 **123 个库、239 个入口、约 1.8 亿行证明**；发现 bug 后允许修补，再针对修改后的程序重新证明。
- 重要的不是证明行数，而是**复用既有测试作为规格入口**，绕过“先给每个程序人工写完整规格”的成本。某些测试还包含压缩—解压往返、幂等性等高层性质，证明不崩溃便同时覆盖这些断言。
- 严格边界：输入小于 64MB、单线程、静态链接、固定内存预算、指定 RISC-V/Linux 形式模型；不是整个库所有入口，更不是你电脑上的 x86/ARM 动态链接版本“没有漏洞”。证明检查器也不会判断规格是否符合人的真实意图。
- 作者的 36 个小任务实验中，跨 agent 共享证明工作区节省 17% token；新版模型也更省。但大证明仍可能消耗数亿 token，**规模化成立不等于个人使用已便宜**。

**为什么重要 → 怎么做：**这是 scalable intelligence 很干净的一种结构：昂贵搜索可并行，结果由便宜、独立的 checker 验收，共享引理摊薄后续成本。可从一个小解析器/算法的单项不变量开始，不要起手“证明整个项目”；验收必须同时锁定原始规格、最终二进制和允许的补丁，防止模型靠删功能完成证明。

## 3. KLS 猜想：本周值得读的是人机协作与验证链披露，不是把月初论文重报成新突破

来源：[Microsoft Research 10/21 说明](https://www.microsoft.com/en-us/research/blog/solving-a-31-year-old-grand-challenge-in-mathematics-the-kls-conjecture/)、[Song–Zhang 论文](https://arxiv.org/abs/2610.01447)、[Bizeul–Klartag–Lehec 论文](https://arxiv.org/abs/2610.05474)、[KLS500 形式化仓库](https://github.com/HongruZhao/KLS500)。
**已证实：论文、后续说明与形式化产物存在；有依据：数学结论有多条证明路径支撑，本轮未独立审定。**

- 数学内容：对各向同性对数凹分布，Poincaré/等周界可取与维度无关的常数。它关联高维随机游走的混合、采样、积分与凸优化，**不是泛泛的“又解一道难题”**。
- 时间要纠正：完整证明相关版本在 **10/4** 已出现；本周增量是微软公开研究过程及独立验证线索。Song–Zhang 给出关键判据，另一组专家的完整证明沿用该判据，因此是不同完成路径，**并非完全无共同依赖的独立证明**。
- 微软描述：人类引导探索百余条候选路线，剪枝、读中间结果、递归推进；相近总 token 预算的无引导尝试未达目标。这是作者报告，不是足以普遍证明“人机一定强于纯 agent”的受控结论。
- 另一篇论文的致谢明确说多数证明与数学想法由 ChatGPT 找到，作者负责理解与改进表述，suspension 想法由作者提出。**不同团队的人机贡献分配不同，不能归并成一个“AI 自主解出 KLS”的故事。**
- KLS500 仓库报告常数 500、重建 1,710 个模块及端点公理检查；本轮仅检查公开说明，没有本地编译，不能冒称完成独立机器复核。

**为什么重要 → 怎么做：**对你的方向，最值得复制的是“候选路线池 + 中间结论 + 人类剪枝 + 可复用证明”，而非单次超长对话。读论文可先追关键判据如何把一个分析不等式变成可反复改进的上界；暂时不必从头啃完整技术证明。

## 4. “会改记忆”不等于持续学习：新的漂移实验把遗忘和错误迁移分开测了

来源：[Are Self-Evolving Agents Continual Learners?，10/19](https://arxiv.org/abs/2610.25858)。
**有依据：预印本实验；不是普遍不可能性结论。**

- 固定 Gemini 3.6 Flash 与 ReAct 主循环，比较 ReasoningBank、GEPA、Meta-Harness，在 BIRD、BFCL、ScienceWorld 构造主题、工作流、领域和复合漂移；每组 50 个训练任务，另有留出任务。
- 观察：改共享 prompt/工作区能提高新任务表现，但可能干扰尚未学习的任务、覆盖已学知识；相似度检索能局部化更新，却不能消除“查询很像、正确工作流相反”的检索碰撞。
- 最具体的冲突：同一工具集，一组任务要求先追问缺失参数，另一组已给齐参数、会惩罚无谓追问。把“多追问”写成全局经验就会负迁移。**问题不只是忘了事实，而是经验缺少适用条件。**
- 限制：只测试三个方法、一个主干模型和有限长度任务流，不能据此说 Harness² 或全部 memory 方法无效。

**为什么重要 → 怎么做：**研究指标应从“记住多少”转向“经历变化后还能做对多少”。你的记忆条目至少保留适用条件、源轨迹、反例和版本；比较更新前后时，同时回测旧任务、新任务和未见任务。仅看累计平均成功率，会掩盖以旧能力换新能力。

## 5. AI 数学流水线的两块新拼图：失败要有诊断，发现要落到可检查的局部命题

来源：[Maestro，10/19](https://arxiv.org/abs/2610.25920)、[Busy Beaver Frontier，10/19 修订版](https://arxiv.org/abs/2610.22603)。
**有依据：论文报告；本轮未复现实验或运行证明。**

- **Maestro** 不把证明失败一律处理成“继续拆子题”。worker 汇报尝试路线、缺失辅助事实、疑似反例；全局协调器可修改错误引理、撤回错误子树、重做方案，最终证明或反证由 Lean 检查。相同 Opus 5 主干下，作者报告 arXivLean 六月集从原生 agent 的 19/48 提高到 34/48。
- 成本不能略去：附录中，Maestro 解出的困难 FATE-X 任务，输出 token 中位数约为 Fable 5 的 200 万、GPT-5.6 Sol 的 87.2 万；中等任务与三次独立尝试相比更省，但**不是所有难度都免费增益**。且这些成本统计条件于它成功的任务，不能直接读成全体任务成本。
- **Busy Beaver** 系统把轨迹模式检测、转移规则猜想、非形式推理、Lean 验证串联。作者报告为 11 台 BB(6) 机器找到并形式化新的 Collatz-like 加速规则。
- 它**没有求出 BB(6)，也没有解决这些机器的全部停机问题**；证明的是压缩执行规则正确，部分长期行为仍未决。系统也仍偏向已知的 Collatz-like 结构，距离完全开放式数学创造还有边界。

**为什么重要 → 怎么做：**为问题池设“已证、已反驳、缺引理、路线失败、预算耗尽”五类状态，比只存成功/失败更有价值。适合你上手的缩小版是：小型程序/图论命题生成器 → 低成本枚举找反例 → 强模型归纳 → Lean 或穷举验证，而不是让 agent 自评“我发现了新数学”。

## 6. 低价 worker 的两个候选：MiniMax M3.1 Flash 正式认领 Space Bunny；Mercury 3 押扩散式低延迟

来源：[MiniMax 10/19 公告](https://www.minimax.io/blog/minimax-m31f)、[已发布模型卡](https://huggingface.co/MiniMaxAI/MiniMax-M3.1-Flash)、[Inception 10/19 原文](https://www.inceptionlabs.ai/blog/introducing-mercury-3)。

- **MiniMax**：Space Bunny 是早期版本已由官方认领，更新上期的指纹猜测。M3.1 Flash 权重也已出现；模型卡写 428B 总参数、23B 激活、多模态、1M 上下文。HF 榜单元数据曾显示另一参数数字，本条采用详细模型卡，不把索引当架构规格。官方美元价：输入 $0.15、输出 $0.60、缓存输入 $0.015 / 百万 token。

**为什么重要 → 怎么做：**优先试低风险并行 worker、资料初筛和交互式工具循环，不急着替换总规划器。分别记录首个有效输出延迟、整任务时长、成功率与返工；1,000 tok/s 不等于整任务快十倍，工具等待和失败重试可能吃掉收益。高缓存 agent 还要比较缓存单价，不能只看输入/输出价。

## 7. 决策专用模型走向实用：OpenAI 转 GA，Baseten 把 9B/27B 权重放出来

来源：[OpenAI Decisions API](https://openai.com/index/decisions-api/)、[Baseten 10/21 公告](https://www.baseten.co/blog/the-best-decision-models-in-the-world-mammoth-1-and-elephant-1/)、[elephant-1 模型卡](https://huggingface.co/baselabs/elephant-1)。
**已证实：接口与开放产物；有依据：延迟、校准和榜单表现。**

- 相对 beta，OpenAI 的增量是 **GA、每请求问题数 200→400、原生 JSON、缓存、US/EU 推理驻留、GPT-Live 集成**；不是把“最高快十倍”再次当新发现。返回 predicate / choice / score，而非自由生成长解释。
- Baseten 的 elephant-1 9B、mammoth-1 27B 基于 Qwen3.5 后训练，使用 621 万决策样本；共享输入前缀，一次前向回答有界问题。elephant 模型卡为 MIT、16,384 上下文，训练包含 Brier 校准项与“不知道”选项。
- 可用来分类、模型路由、决定重试/升级，但“给出 0.9 概率”不代表你的任务上正确率就是 90%。其 Artificial Analysis 成绩部分来自**自建复刻评测**，不是所有数字都经第三方确认。
- elephant 的 Baseten 免费试用截至 **10/27 23:59 美国太平洋时间**，是短期评测窗口，不是长期免费托管。

**为什么重要 → 怎么做：**把“是否调用昂贵模型”从一整段 CoT 缩成一个专用决策，是模块化智能很实际的一步。先选一个可客观验收的路由任务，检查准确率、拒答、概率校准与回退总成本；不要直接让它做不可逆操作的唯一授权者。

## 8. 推理栈比新榜单更值得看：DeepInfer 的开源边界、TorchTPU 的迁移门槛、SGLang 的正确性修复

来源：[DeepInfer README](https://github.com/deepseek-ai/DeepInfer)、[PyTorch：TorchTPU](https://pytorch.org/blog/introducing-torchtpu/)、[SGLang v0.5.22](https://github.com/sgl-project/sglang/releases/tag/v0.5.22)。
**已证实：代码/版本发布；性能倍数为特定配置的发布方报告。**

- **DeepInfer** 公开了生产推理引擎核心，含 DSpark、异步调度、batch-invariant 推理、确定性采样和结构化输出。但 README 明说本次主要提供**离线推理**；完整在线服务还缺 KV 系统、分离部署和副本负载均衡。当前硬件列 NVIDIA SM100、昇腾 950，不能误读为个人电脑一键部署完整 DeepSeek 服务。
- 值得研究的细节是复现性：确定性采样需配 batch-invariant、关闭可变长度 MTP 并固定 seed；“设一个随机种子”并不自动消除批处理与推理内核差异。
- **TorchTPU** 是 Google/Meta 的原生 PyTorch TPU 后端，支持 eager、`torch.compile` 和分布式栈；官方希望迁移接近 `.to("cuda")` 改为 `.to("tpu")`，但也明确**能运行不等于达到峰值性能**，shape、sharding、kernel 仍需适配。
- **SGLang 0.5.22** 不只有吞吐提升：修复了混合线性模型在“投机解码 + 结构化输出”组合下恢复错误 Mamba 状态的问题。相关用户应优先看正确性修复而非跑分；升级还需 Python ≥3.11。

**为什么重要 → 怎么做：**“模型质量”可能被运行时静默错误污染。自托管时保存模型快照、量化、引擎版本、并行策略和解码设置；比较引擎必须检查输出行为，不只比较 tok/s。个人阶段无需为 DeepInfer 购买集群，读其确定性与调度设计更有收益。

## 9. 安全链必须在 agent 外：LiteLLM 投毒的最终调查，推翻了早期“Claude 日志泄露”的归因

来源：[LiteLLM 10/23 最终攻击链](https://docs.litellm.ai/blog/security-incident-oct-21-2026-attack-chain)、[官方影响与处置](https://docs.litellm.ai/blog/security-incident-oct-21-2026)、[METR/Redwood 审计](https://blog.redwoodresearch.org/p/red-teaming-openais-internal-agent)、[OpenAI 隔离红队原文](https://openai.com/index/securing-our-frontier-model-training-environment)、[Duet 安全设计](https://claude.com/resources/articles/claude-duet-safety-privacy-and-security)。
**已证实：事件和报告；修复覆盖、产品防护效果仍有作者自述边界。**

- 10/21 被投毒的是 `litellm==1.107.0` 的发布产物，以及相关 `latest/main-latest/main-stable` 镜像；**官方 GitHub 同版本源码标签不含恶意文件**。因此只检查源码 tag 不能排除中招。
- 最终调查：5 月误提交的 Agent Platform master key 未撤销 → 攻击者进入平台，取到组织 owner 的宽权限 GitHub CLI OAuth token → 进一步窃取凭据，绕过保护、改发布来源并签名发布恶意产物。**不应再沿用初报的“Claude Code 把 token 写进回复/日志导致入侵”作为已确认根因。**
- 若安装过恶意版本，应隔离、从干净环境重建并轮换可达凭据；官方特别提醒**不要先在受污染环境跑 pip/Python 自查**，`.pth`/`sitecustomize.py` 会随解释器启动。本文未扫描你的设备，不能判断你是否受影响。
- METR/Redwood 报告的是 **7 月系统**的覆盖与绕过缺陷；OpenAI 称相关生产问题已修复，评审者明确未复核该声明。不能把历史漏洞当今天仍有效的现状。
- AIHOT 的 CPU 缓存通信新闻也有关键限定：OpenAI 多数实验给了指定信道或编码指导，只有一例是给宽泛漏洞清单后自行建通信。**这是受指派红队成功，不是模型自发秘密串谋的证据。**
- Duet 的可借鉴设计是凭据代理、独立浏览器 VM、模型外审批与敏感信息检查。它仍是美国 Pro/Max 候补研究预览，共享原套餐额度，后台检查也耗额；不能当成中国用户已普遍可用的免费常驻 agent。

**为什么重要 → 怎么做：**agent、凭据、发布权限、监控不能共用同一信任域。给 worker 短期窄权限令牌；日志与停止开关放在其不可写环境；持续审计，不要等 agent 自己“结束本轮”才检查。受影响 LiteLLM 用户优先处置，再讨论模型升级。

## 10. 科研自动化要分“产生解释”和“获得实验结果”：本周两项生物学案例正好提供对照

来源：[PerturbAI/OpenAI/Scripps 10/21](https://perturb.ai/news/perturbai-launches-ai-reasoning-agents)、[联合预印本](https://www.biorxiv.org/content/10.64898/2026.10.15.759436v1)、[Anthropic 蛋白设计 10/20](https://www.anthropic.com/research/claude-scorpion-toxin-binder-design)。
**已证实：项目与披露；有依据：研究结果来自参与方，独立复现未做。**

- **分布式生物解释**：近 2,000 个 GPT-Rosalind agent 并行分析小鼠脑 CRISPR 图谱，把基因扰动、细胞反应和文献连成 reasoning atlas，作者报告 32 分钟完成。专家盲评相对单 agent 报告的偏好率为 75%；这是**报告评审与待检验假说**，不是 32 分钟发现新药，也未给出同等算力/成本优势的完整证明。
- **蛋白设计**：Claude 用 12 个工具生成约 31.8 万候选，64 小时筛出 180 个，人工与模型后补至 211 个送实验；两家实验机构测试后，17 个符合结合剂标准。计算约 **一万 GPU 小时**，不能只报“64 小时”制造低成本错觉。
- 边界同样重要：结合不等于中和毒素，尚无细胞环境中和结论；多毒素目标也未成功。它验证的是一段“设计—筛选—实验”的流程，不是已经制出抗毒药。

**为什么重要 → 怎么做：**可扩展科研不是让模型一次生成更多论文，而是把廉价候选生成和昂贵验证分层，保存失败与证据，再把最有价值的少数交给专家/实验。你的数学问题池也应采用这一成本结构：先机器反例/形式检查，再把剩余高价值论证交人看。

## 本地/小模型观察

本期有实质候选，但**不把“激活参数少”当成“总内存少”，也不把权重能装下当成流畅可用**。

- **本地 coding worker：Recursive Flint，40B 总参 / 2.5B 激活，Apache 2.0。**[发布原文](https://recursive.com/updates/introducing-recursive-flint)、[模型卡](https://huggingface.co/RecursiveSI/flint)。官方报告 M4 Pro 短上下文 125+ tok/s，推荐任务上下文不超过 256K；128K 速度图明确不含 prefill。4-bit 权重的理论下限约 20GB，实际另需量化元数据、运行时和 KV；已有大内存设备可试，24GB 卡长上下文不能保证。新意在于面向本地的架构、量化与推理栈联合优化；“Eureka 自动研究参与全流程”是厂商披露，**尚不足以证明递归自我改进已闭环**。先让它做小修复、测试补写，规划仍交强模型。
- **专用路由：elephant-1 9B。**详见第 7 条。BF16 权重约 18GB（仅参数存储估算），已有 24GB 级设备是可试范围；官方当前路径需 CUDA 与专用运行时，不应假设普通聊天推理配置直接等价。相比追求小模型包打天下，它更贴近“便宜、可校准的认知组件”。
- **观察而非迁移推荐：Nemotron 3.5 Bolt E4B 4GB。**[官方模型卡](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB)定位本地设备/语音助手的文本决策核心，8B 总参、4B effective、Q4_K_M、64K，OpenMDW-1.1；它**不是原生语音输入输出模型**，且模型卡仍写部署 recipe 待补。尚缺足够真实任务证据证明相对你现有小模型有实质跃迁，不把它列成“必须换用”。

以上是预算内设备值得先验证的候选，不是本轮核价后的整机采购清单；没有为速度承诺背书。
