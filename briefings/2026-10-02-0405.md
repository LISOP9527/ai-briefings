## 1. Claude Code mods：harness 本身变成可编程对象（头条）

**来源**: [Anthropic 官方博客](https://claude.com/blog/claude-code-mods)（10/1）· [HN](https://news.ycombinator.com/) · [Claude Devs 教程](https://claude.dev)
**状态**: 【已证实】

mods 是挂在 Claude Code 事件流上的小型 TypeScript 函数：可改写提示词、拦截/重试工具调用、审批权限请求、改 UI，可在事件前/后/替换执行。关键设计点：
- mods 随插件分发，`/plugin` 安装，CLI 和桌面端都可用；可以让 Claude Code 给自己写 mod 并热重载。
- **官方开始把内置功能下沉为 mod**：`/diff` 已是 mod，计划把更多内置功能迁过去——"把 Claude Code 削到小内核，只加回你要的部分"。
- 无沙箱，与 Claude Code 同等机器权限——装第三方 mod 等于装任意代码。

**为什么重要**：和你跟踪的方向直接相关——过去一个月的三个信号连成线：mods（功能可替换）、OpenRouter 的 eval-CI/置信度路由教程（harness 决策可测试）、以及第 5 条的论文簇（上下文管理变成策略）。**harness 正从"固定胶水"变成"用户可编程层"**。对你的实际意义：自定义工具调用审批、按任务类型动态改 system prompt、把内置功能换成自己实现——这些以前要 fork 的事现在是一段 TS 函数。

**你可以怎么做**：`/plugin` 里直接装；写 mod 前先想清楚是"前/后/替换/包裹"哪种事件挂钩；第三方 mod 按装 npm 包的同等警惕对待。

## 2. 决策模型生态一天内开源化+平台化：Cloudflare Clef / laya / LLM2Jev

**来源**: [Cloudflare 博客](https://blog.cloudflare.com/clef-decision-models/)（10/1，HN 459 分）· [Workers AI changelog](https://developers.cloudflare.com/changelog/post/2026-10-01-clef-workers-ai/) · [HF: convaiinnovations/laya](https://huggingface.co/convaiinnovations/laya) · [arXiv 2610.02076](https://arxiv.org/abs/2610.02076) · [InfoQ: Jev 正式发布](https://www.infoq.com/news/2026/10/typesafe-ai-jev-released/)
**状态**: 【已证实】（权重已在 HF，Apache 2.0）

- **Cloudflare Clef / clef-flash**：Cloudflare 自训的首批开源权重决策模型，27B 多模态（状态可以是文本/JSON/图片/视频），Jev-API 兼容，自称在 Jev Decision Index 上当前第一，上 Workers AI（$0.24/M 输入）。同时发布 **RL 微调平台**：先用 FDE 模式合作，后转自助——把"专用决策模型微调"做成云服务。
- **laya**（HF 趋势榜首，4868 likes/周）：非自回归 System-1 决策模型，单次前向 ~33ms、100+ 语言，用严格 proper scoring rule 做 RL（RLCD）训练——诚实报概率是唯一最优策略，输出数学上校准。`pip install laya`，自带 MCP server / LangChain 集成；实测微调后 0.362→0.766。
- **LLM2Jev**（arXiv，10/1）：证明现代 LLM **天然就是决策模型**——不用训练，直接从方括号数字标识符的 next-token 概率读出校准决策；4B 零样本即追平同骨干的社区决策模型，还自带多模态决策能力。微调只在大选项数路由等特定任务上值得。
- 背景：Jev（TypeSafe AI，Diogo Almeida 创立）已公开发售，InfoQ 10/1 报道。

**为什么重要**：上月开始的"决策模型"生态这周越过临界点——**有了开源权重（Clef 27B）、托管服务（Workers AI）、微调平台、训练框架论文（LLM2Jev）、和校准训练方法（laya 的 RLCD）**。agent 栈里"分类/路由/审批/打分"这一层正在从"让 LLM 输出 JSON"迁移到"专门的单次前向决策模型"，成本低两个数量级且可校准。LLM2Jev 的结论尤其省你钱：先别微调，直接用训练-free 读数测。

**你可以怎么做**：路由/guardrail/审批类的 worker 可以试 clef（本地跑 27B 需要 ~60GB+，2 万元设备勉强）或 laya（轻得多，33ms）；benchmark 自己流量时看 jev-1.13 的 jaggedness 页（计数/算术/日期比较不可靠——数学留在代码里）。

## 3. 路由器从概念到实测：LangChain -64% 成本实证 + Weave Router 2.0

**来源**: [LangChain 博客](https://blog.langchain.com)（10/1，一手）· [Show HN: Weave Router 2.0](https://news.ycombinator.com/item?id=49911500)（93 分）· OpenRouter 教程两篇

## 5. 蒸馏攻击后续：同一手法在 Azure 上直到 9/27 仍可抽取 GPT-6 Astra 推理

**来源**: [The Decoder](https://the-decoder.com/openai-says-it-stopped-a-campaign-to-steal-its-models-reasoning-but-the-trick-still-worked-on-azure/)（10/1）· [Schaeffer 团队 X](https://x.com) · TPS Report
**状态**: 【已证实-研究者复现报告+OpenAI 确认攻击路径真实】

接上轮 OpenAI 蒸馏披露。Schaeffer 团队同日发更新：9/13 复测，OpenAI/Anthropic 自家 API 已封死，但 **Azure 上所有测过的 OpenAI 模型（含 GPT-6 Astra）+ Anthropic 模型（至 Sonnet 5）仍可被"解密预言机"手法逐字抽出推理轨迹，一次请求即成**。OpenAI 到 9/27 才给 Azure 端点加防护——**自管 API 修好不等于生态修好**。手法原理：推理块用共享密钥加密返回给客户端转发，因此可跨会话/跨用户/跨同系模型搬运，让便宜的同系模型当解密器。

**为什么重要**：(a) 工程教训——任何"服务端加密、客户端转发"的设计都要假设密文会被跨上下文重放；(b) 行业教训——模型通过多云分发时，最弱平台决定整体防护水位；(c) 跟进上轮的 IP 博弈线：这次披露说明防护是"逐端点打地鼠"而非协议级修复。

## 6. 论文簇：上下文/经验正在从 harness 外部状态变成模型策略内对象

**状态**: 【已证实-均为 arXiv 新论文，结果未经复现】

本轮 arXiv 有 5 篇同方向的工作同时出现，值得作为方向信号打包看：

- **Context Language Models**（arXiv 2609.37725，UW+Meta Superintelligence Labs，HN 121 分）：把 context 当成模型可任意改写的文件来管，零样本超 SOTA 上下文管理策略——BrowseComp-Plus 准确率 +11.4% 且 FLOPs -21.5%，12 小时 EdgeBench +5% 且 FLOPs -59%，24 小时多仓库 agent-swarm +65%；还能用自然语言指令经 skill-optimization loop 引导（held-out +35.9 分）；在线 RL 让 Qwen3.5-9B 在 BrowseComp-Plus **+47.6%**；配套 Suffix Cache Reuse 服务端再省 35%。**上下文管理从 harness 职责变成模型内生行为**。
- **AutoCompact**（arXiv 2610.02163）：训练 coding agent 自己决定何时压缩、保留什么、如何续跑；SWE-bench Verified +9.2%、SWE-PolyBench +5.0%，256K 窗口不再溢出，16K 窗口也提升——**compaction 从"溢出兜底"变成"策略决策点"**。
- **Component Routing**（arXiv 2610.01787）：把 agent 轨迹拆成 locators/procedures/state facts/lessons 四类成分，分别路由进权重或 context——locators 和 lessons 进权重好、procedures 和 state facts 进 context 好；用"复现频率+状态条件性"两个预训练前可测的属性，24/24 格子预测对了最优去向，比单一去向基线 +3.5 分。**"经验该不该进权重"第一次有了可操作判据**——和你 scalable mind 方向里"什么该固化、什么该外置"的问题同构。
- **Mem++**（arXiv 2610.02002）：非破坏性记忆——写入时不蒸馏、整篇带日期作者存，读取时按时间点检索+词义融合；OrgMemBench 超最强记忆系统 8-13 分。**反对"写入时压缩"的主流做法**：先把可答范围锁死是 memory 系统的隐性损失。
- **The Missing Primitive**（arXiv 2610.02191）：把数学推理拆成 Discovery/Generation/Digestion/Execution 四原语测，发现**正确率掩盖能力剖面，Discovery 是主要瓶颈且最容易修**；primitive 引导的自蒸馏稳定提升。**对你的含义**：AI 数学流水线里"找问题/找路子"（Discovery）比"写证明"更缺，资源该往前端堆。

其他值得一提：Mingbird（见本地版块）、KaliBench（安全工具使用基准）、"Keyword Harnesses Fail Open"（小模型工具调用声明的廉价诊断梯）、"Agents Are Systems, Not Models"（agent 评测方法论）。

## 本地/小模型观察

本期有实质内容：

- **Mingbird**（arXiv 2610.02001，10/1）：本地优先的 agent harness（Windows+Ollama），用 10 个机制逐点补偿小模型失败形态（字节级 net-zero prefill 预算、完成前重读任务的 finish gate、签名级循环检测）。受控对比 4 harness×4 模型×18 任务：**Mingbird 0.886 vs goose 0.631 / opencode 0.479 / agent-mini 0.405**；τ²-bench 0.856 vs 0.791/0.737。最关键的旁证：**同一批任务上前沿模型在不同 harness 间从 0.997 跨到 0.478**——harness 质量对小模型的决定性大于模型本身。作者自报局限：自建 benchmark、单机、单次计分（同臂复测波动 ±0.069）。【已证实-方法公开，结果待复现】
