## 2. Anthropic 内部研究模型攒出 5 条真实攻击链：Chrome 一键 RCE、Safari 跨域读、Linux 内核零交互 root——62 个 CVE 已修

来源：[Anthropic Research 原文](https://www.anthropic.com/research/discovering-vulnerabilities-with-claude)、[TheHackerNews 逐条拆解](https://thehackernews.com/2026/10/anthropics-unreleased-ai-model-chains.html)、[wheresthe.ai 存档 PDF](https://wheresthe.ai/archive/us-anthropic-unreleased-model-builds-five-exploit-chains-in-browsers-and-os-2026-10.pdf)、[HN](https://news.ycombinator.com/item?id=50270131)。
**已证实：5 条链的技术细节与修复版本公开可核查（Chrome 156 release notes 署名 "Xinyang Ge of Anthropic, assisted by Claude"；Apple iOS 26.5.2 署名 "Milad Nasr and Nicholas Carlini with Claude"）；有依据：漏洞由模型自主发现并串链为自报，Chrome 侧为「初步提示后」完成。**

- Chrome 链（一键、macOS 默认配置）：V8 堆破坏 → 第二个洞逃出 V8 内存沙箱+破 ASLR（ROP 接管 renderer）→ CacheStorage 竞争读越界摸清高权限进程布局 → FedCM UAF 出沙箱执行任意代码。共向 Google 报 **62 个洞全部获 CVE 且已在 Chrome 156（10/20）修复，含 13 个沙箱逃逸**。
- Safari 链：不执行代码，串联多个洞拿到浏览器内存读写后只改一个值关掉同源策略——之后任意网页可读历史/cookie 并代发已登录请求。
- Android/Windows/Linux 各一条；Linux 内核那条是未认证远程 root。协调披露 90+45 天，细节只公开已修部分。
- 定性要准：这不是「跑了个 CVE benchmark」，是厂商修复记录里可查的**已闭环战果**——证据强度高于 Carbon 的榜分。但注意论文措辞：「little to no user interaction」指受害者侧，模型侧仍有「initial prompting」与内部 harness，自主程度未知。

**为什么重要 → 怎么做：**(a) 立即动作很朴素：**Chrome 升到 ≥156、iOS ≥26.5.2**——这批洞在野利用价值极高，披露窗口已在走。(b) 对你的流水线，这是「验证成本决定领域」的又一数据点：网安领域验证 = 跑一遍 PoC 看是否执行成功，和 Lean 一样是廉价机械验证——所以攻防是继数学之后第二个被流水线化的领域，不是巧合。(c) 供给端判断要更新：未发布模型的网安能力已显著超出公版（62 CVE vs 公开榜分），你评估任何「本地模型做安全审计」的方案时，对手方假设应上调一档。

## 4. Qwenputer：把确定性 RISC-V CPU 编译进 Qwen3.5-4B 的权重——GDN 层当精确 RAM，还能存文件

来源：[博客原文](https://divagr.com/blog/qwenputer)、[HF](https://huggingface.co/divagr1925/Qwen3.5-4B-Qwenputer)、[GitHub](https://github.com/divagr18/qwenputer)、[HN](https://news.ycombinator.com/item?id=50282838)。
**已证实：权重、代码、riscv-tests 通过与 qemu 对照 23 万条输出位零失配为作者自述但全部可复现（24GB 单卡可跑）；「隐藏推理」与「权重内监视器」两篇衍生文同作者。**

- 机制：Qwen3.5 的 Gated DeltaNet 层在 gate=1、β=1、one-hot key 下变成**精确可寻址 RAM**（状态大小不随上下文膨胀，代价远低于用注意力当 RAM）；一个编译器把 RV32IM+Zba CPU 描述逐指令编译成 transformer 层（注意力做查表、FFN 做运算、DeltaNet 存 RAM），占前 11 层，无训练。模型复用 tool-call 格式内部调用，无外部运行时。18M 指令零错误；大数运算 48.6%→100%，与外挂 Python 工具持平；对正常文本能力无影响（KL 6e-4）。
- 更邪门的延伸：权重内文件系统——文件名哈希进 DeltaNet 状态的 1024 槽，正文按 8 token/行存，跨会话持久；实测「上一会话存的事实」90% 答对 vs 把旧会话贴回去的 30%，与 Python 记忆工具持平。也就是说**持久记忆可以不靠外部存储、写进（追加层的）权重**。
- 安全两面：同作者的后续指出 (a) hybrid 模型能把推理藏进 RNN 状态、**绕过 CoT 监控**；(b) 反向用——编译进权重的监视器模型自己关不掉。RNN 状态的可写性同时是礼物和盲区。

**为什么重要 → 怎么做：**对你的 scalable mind 主题，这是「第三条记忆/计算路径」的完整样品：KV 缓存（贵且易失）、外部工具（有 IO 边界与监控面）、**权重内编译结构（确定性、可持久、模型无法篡改、但也监控不到）**。可操作：(a) 24GB 就能跑，值得亲手把 `rv-store` 分支的文件系统试一遍——它是「跨会话记忆写进模型本身」目前唯一可玩的开源实例，与上期 Stratum 的「持久记忆实证」互补（一个改架构，一个改存储）；(b) 注意它的正确性来源是**编译不是学习**——生成-验证不对称的极端形态：正确性免费，因为根本没有生成。

## 7. arXiv 速递：ATP 的 bitter lesson、科研 agent 的廉价 TTS、缓存错误集成、TTT（有依据，未复现）

- **[h1: A Taste of the Bitter Lesson in Automated Theorem Proving](https://arxiv.org/abs/2610.35962)**：不做分解/搜索结构、只给模型高效 Lean 接口+验证反馈的简单 agentic loop，在 PutnamBench/FATE-X/FormalConjectures100 追平或超过 Goedel-Architect、AlphaProof Nexus 等专用工作流，**解出 8 个 FormalConjectures 开放问题，且 pass@1 经常就够**。消融显示差距主要来自「执行反馈接口效率」而非编排。——直接支持第 4、5 条的判断：先打磨 verifier 反馈回路，再谈精巧分解。
- **[MLE-World](https://arxiv.org/abs/2610.37175)**：用 Qwen3.5-4B 微调一个世界模型，**不真跑实验就预测 ML 程序的终态输出**（报错/训练日志/验证分+置信度），一次推理替代一次训练——让研究 agent 的 test-time scaling 变得付得起。你的「候选→廉价筛」流水线可照抄这个「predict-first 过滤层」。
- **[Agentic Algorithm Design](https://arxiv.org/abs/2610.35595)**（Lehre，演化算法理论名家）：agent 提黑盒优化算法设计 → Lean guard 刷掉有缺陷的 → agent 定义势函数并证 drift bound 保证期望运行时间。**「提出+形式化+证明」完整闭环的又一实例**，且作者是该领域正牌专家而非 AI 团队。
- **[Silent and Costly: Prompt-Caching Mis-Integration](https://arxiv.org/abs/2610.34817)**：10 个流行开源 agent 系统的 120 个缓存相关 PR 实证——请求侧配错+读侧计数错普遍存在且**大多静默**，正好解释 linux.do 上「走中转站几乎不命中缓存」的抱怨。先量化你自己 harness 的缓存命中率，再谈模型成本。
- **[Select-TTT](https://arxiv.org/abs/2610.36794)**：In-Place TTT（拿 MLP down-projection 当 fast weight）在真实长文 QA 上失效的根因是均匀写入稀释了相关内容；按 query 相关性选择性写入修复。——「往权重里写临时记忆」路线的又一块拼图，与第 4 条 Qwenputer 同一问题域。
- **[When the Critic Falls Behind](https://arxiv.org/abs/2610.36826)**：rubric 与 harness 共进化的 Tsinghua 工作（上期 RuHarness 同源）——如果你的问题池评审也想做持续进化，这是可参考结构。

## 本地/小模型观察

本期有一个头号可玩件、两个真实跃迁、一组配套工程：

- **Qwenputer（见第 4 条）**：4B 基底+编译层 ~18.8GB，单张 24GB 卡可跑——**2 万元内能玩「权重内确定性计算+持久记忆」的唯一实例**，也是把「RNN 状态当 RAM」从论文变成玩具的样本。首选。
- **NVIDIA Nemotron 3.5 Transcribe（30B-A4B，OpenMDW-1.1）**：open-weight 可提示 ASR——40 语转写、31 语互译、≤8 说话人归属、1 小时录音、词级时间戳；Open ASR 榜开源第一（英 4.71%/多语 4.62% WER），ContextASR-Bench 实体错 -6×；BF16/FP8/NVFP4/GGUF 齐发，激活仅 ~4.3B。局限：离线录音非流式。**本地语音管线里把 ASR+说话人+翻译三件套合成一个模型**，比串 Whisper+pyannote+翻译干净一档。
- **MiniCPM-OCR 系列**（面壁，开源）：1.3B 解析+2B 判别，Real5-OmniDocBench 93.68、OCRBench v2 54.7 SOTA，DSpark 加速后 1.2 页/秒；同窗口百度 Unlimited-OCR-2（3B）也在榜——**文档解析这个工位的小模型密度正在快速上升**，配你的「批量读文献」管线够用。
- **Nanbeige4.3-33B**（Apache-2.0，BOSS 直聘旗下实验室）：dense 33B、512K 上下文、agentic 教师模型，自报 Terminal-Bench 2.1 80.9（Qwen3.8-27B 73.0）但未被独立复现；明确定位是为后续 **3B 蒸馏**铺路——33B 本体重（BF16 ~66GB，单 24GB 卡需量化），真正的看点是官宣要做的 4.3-3B，先记着。
- **工程信号**：llama.cpp v0.8.0 一次吃进 LFM3 全家、DS V4.1 Flash、SenseNova U1、Flint、Muse Spark 等，并新增 `/v1/realtime` 与 `/tts` 端点——本地推理栈开始把**实时音频**当一等公民，配合 LFM3-Audio 与 Transcribe，端侧语音 agent 的积木基本齐了。
- **附带**：商汤 SenseNova 6.8 Code2Video（27B 开源，先生成特效代码再渲染）思路对需要精确可控视频的场景有用；linux.do 在讨论 Claude Code「破甲」与中转缓存不命中——后者已被第 7 条论文系统证实是普遍集成错误而非你的错觉。
