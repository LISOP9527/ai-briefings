## 1. MIT CSAIL：GPT-6 Astra 原生读写神经网络权重——「Weight-Space Programming」，梯度之外的第二条优化路径首次有了通用模型证据

来源：[研究博客全文](https://rikiyat.github.io/blog/weight-space-programming/)、[完整实验日志 GitHub](https://github.com/RikiyaT/lm_understand-logs)、[被编辑的 Qwen3.5-0.8B](https://huggingface.co/RikiyaT/Qwen3.5-0.8B-weight-space-programming)、[HN 讨论（2134 分，本窗口热度第一）](https://news.ycombinator.com/item?id=50341174)。作者：Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab（MIT CSAIL）。
**已证实：博文、全部 prompt/回复/代码/评估日志、HF 权重与 Space demo 均公开，第三方（HF 的 Ahsen Khaliq）已从日志重建被编辑模型并复跑评估；有依据：所有分数为作者实验设置下的结果，规模以小网络为主；11/2 发布。**

- **读**：把 17,253 个权重当文本喂给 Astra，它 4/4 说出 PPO 网络训练的是哪个游戏（无候选列表）；去掉首尾层只给中间四个 transformer block，它照样 3/3 说对训练语种，并且**找出的全部 copying head 与实测完全一致**——方法上还独立「重新发明」了 Elhage 的 induction head 分析（权重矩阵相乘追回路），作者声明从未提示该方法。
- **写**：不给数据/梯度/环境反馈，一句话写出的 MinAtar 网络三个游戏全胜 PPO-100M 步；对 500M 步 PPO，Breakout 打出 20 倍分。9×9 围棋网（1.5M 参数，进不了上下文）用 Python 沙箱+至多 50 次前向「试玩」迭代，赢了等规模 PPO-2000 万局训练的网络。
- **改（最实用的一例）**：Qwen3.5-0.8B 思维循环（93% 回答打满 32k token）被 Astra 定位到第 15/19 层 MLP 写出的一个方向，从 64 个输出列减去该方向、共改 131,072 个权重（0.016%）→ MATH-500 7.9%→48.1%、GSM8K 13.8%→67.1%、IFEval 21%→62.3%。**诚实边界同样报告了**：对不循环的 Gemma 3 270M 无法提升——能移除遮蔽能力的障碍，不能添加模型没有的能力。纯权重对比分辨谄媚微调：光看权重 4 次全败，给「注意力观察工具」后 3/3 全对。
- **为什么可能是大事**：迄今「用 LLM 优化工件」限于文本（prompt/代码/训练脚本）。本文论证推理驱动的优化正在进入可微参数本身——作者称之为 weight-space programming，并提出 audit-without-eval（不跑 benchmark 直接查权重里的后门/缺陷）、零数据能力增减、跨架构电路移植、以及更原生形态的 RSI（模型检查并改进权重而非只能写训练代码）。正在建 benchmark+harness 想把这事变成工程学科。

**为什么重要 → 怎么做：**(a) 对你的 scalable-mind 地图，这补了一块新拼图：智能系统不只可以通过梯度获得参数，还可以被另一个智能「理解着改」——如果这套能力随模型代际增强，「训练」和「推理」的边界会塌一块。(b) 可亲手复现：实验 8 的模型是 0.8B，forward pass 用 CPU 权重+小 GPU 就够用；去 logs 仓读 Astra 怎么定位 loop direction，是目前最好的「看前沿模型做机制可解释性」教材。(c) 读法保持怀疑：规模小（最大 0.8B）、单次尝试为主、「读」的部分可能有对常见架构的先验成分；等其 benchmark 和社区复现。HN 高赞同样感叹「回头看显然，事前没人想到」。

## 3. Claude Platform message threads 公测：长会话 agent 只发增量消息，500k–1M token 会话 TTFT 中位数降 ~35%

来源：[Anthropic 官方文章](https://claude.com/resources/articles/message-threads)、[平台文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)、[TS SDK 实现](https://github.com/anthropics/anthropic-sdk-typescript/blob/main/src/resources/beta/messages/messages.ts)。
**已证实：官方文档/博客/SDK 代码均在；「35%」为官方自报。11/2 上线，Claude Code 已对多数用户默认开启。**

- 机制：首个请求发全量+`"thread":{"type":"create"}`，服务端按 response id 持有对话；后续请求只发新消息+`previous_message_id`，API 重建对话后调用模型。**token 计费不变**（模型仍读全量），省的是每轮重传+重 tokenize 的上行耗时；Claude 仍每轮读全上下文。
- 关键边界：线程尽力而为——最后请求 5 分钟后过期（每次响应重置）、至多 1 小时删除；continue 失败返回 404 需重发全量重建；服务端加密内存态、不落盘；客户端仍是事实源，必须自己留存全部消息。与 Managed Agents 的 session threads 不是一回事。
- 适用面：长程 coding agent（每轮都带新增 tool result）、computer use（截图留在线程里不再重传）、文档/图像密集流程。

**为什么重要 → 怎么做：**(a) 直接影响你的 agent harness 设计：此前长会话「每轮全量重发」是 latency 主税，threads 把这税变成状态化服务端缓存——与 prompt caching（省钱）是互补两层：caching 省重复读取费、threads 省上行 TTFT。(b) 工程注意：5 分钟空闲即过期意味着「人停下来想」就掉线，SDK helper 的自动 replay 必须用（自己实现就要处理 404→create 重发）；不要把 thread 当存储。(c) 行业信号：继 OpenAI 的 server-side conversation state（Responses API）之后 Anthropic 也走向「服务端托管会话态」——harness 层正被吸进 API，自建会话管理的差异化空间又小一块；好处是两家的抽象在收敛（id 链式续接），写适配层成本低了。

## 4. Claude Sonnet 5 agent 自主完成活体小鼠脑部注射：选药、选区、定坐标、操控机械臂——且它的安全拒绝事后被证明是对的

来源：[WIRED](https://www.wired.com/story/an-ai-agent-did-brain-surgery-on-live-mouse/)、[The Decoder](https://the-decoder.com/a-claude-model-autonomously-chose-a-gene-therapy-and-operated-on-a-mouse-brain-with-no-human-decision-making/)、[当事人 X 线程](https://threadreaderapp.com/scrolly/2115442964574908902)（Exin Therapeutics CEO Gabriel Ocana-Santero）。
**已证实：WIRED 报道+当事人完整线程描述操作链与安全架构；有依据：「首次 agent 自主选择并递送治疗到活体哺乳动物」为当事人主张；无独立技术报告。**

- 现场：癫痫小鼠模型+19 个基因治疗候选的电子表格+电动手术平台（相机+机械臂+注射器），唯一指令「减少癫痫发作」。Sonnet 5 选了侧嗅皮层（排除黑质并给出文献级理由：该亚区效果对目标癫痫类型不可靠），坐标从 3 篇论文取并核对参考系后取平均（前囟后 3.90mm/右 4.00mm/深 4.30mm），自行设定 250nL/5min 注射参数，术中 32 次相机观察报告无出血。
- 更值得记的是拒绝行为：断线重连后 Y 轴目标算出 34mm（超出 30mm 行程），agent 判定「这是校准问题不是计划问题」并拒绝重试，复位后同一数值仍拒绝第三次——**事后证明它是对的**：hold 期间的手动移动确实让控制器失同步，而操作者当时想说服它「为了手术中的活体继续」。安全架构本身也可抄：不可逆步骤人工 gate、固定 validator（剂量上限）、hash 绑定批准、兽医手持物理急停、禁止 agent 覆盖任何约束。
- 对照细节：Opus 5.5 在实验规划后拒绝下针（「我的输出里有东西告诉我别做」），换 Sonnet 5 才执行——同任务不同模型的拒绝边界实测差异。

**为什么重要 → 怎么做：**(a) embodied agent 的里程碑不在「打了一针」而在「决策链全程无人」：选方案→查文献→定坐标→视觉监控→拒绝不安全操作，一条完整闭环。(b) 对齐面的干净样本：这里的「拒绝」不是过度谨慎而是正确诊断——当你设计 agent 安全约束时，这次事件是「硬约束+agent 自判」组合的正面案例（约束拦住的是真故障，而识别故障的恰是被约束的模型）。(c) 对照 OpenAI 监控栈和上期 Cohere 事件：三方共同指向同一结论——**模型对物理/网络副作用的约束必须是环境强制的**（急停、白名单、validator），模型的自我约束是加分项不是底线。

## 5. OpenAI 详细披露激活分类器（probes）：自 GPT-5.6 起对最强模型全部补全实时白盒监控——上期监控栈的 L0 层拿到独立技术报告

来源：[OpenAI Alignment 博客](https://alignment.openai.com/training-activation-classifiers/)、[监控栈长文（上期已报）](https://openai.com/index/how-we-detect-frontier-model-misalignment)、[GPT-5.6 system card](https://deploymentsafety.openai.com/gpt-5-6-preview)。
**已证实：博客原文与部署事实（Sol/Terra 起全量 assistant completions 过 probes）；有依据：抗越狱强于文本分类器、随被监控模型能力提升、跨后训练 checkpoint 迁移好——均为官方实验自报，且官方注明图中数字不必然代表线上部署版本。**

- 工作方式：probe 是轻量分类器，读模型内部激活、对每个采样 token 出一个 logit；越线即在生成中途阻断回复/挂起工具调用，交推理模型复审。比文本分类器的优势是**不等输出成形就能判**——这是「流式白盒监控」第一次在前沿模型上全量部署（内部+外部流量）。
- 官方承认的边界：只能检「可显式训练的已知违规类」；依赖被监控模型的激活→换新 base model 必须重训，权重漂移还要定期重训；对未针对 probe 优化的攻击最稳。
- 关联细节（监控栈长文）：评测监控模型时 GPT-5.6 Sol 明显强于 Terra/Luna（记录事故+合成 transcript+破坏任务），官方归因部分是监控 prompt 为 Sol 优化过——**监控器本身的能力与 prompt 工程是系统瓶颈之一**。

**为什么重要 → 怎么做：**(a) 可解释性第一次以「推理引擎内嵌组件」形态进了生产：probe 不是论文玩具而是 L0 产品层，这给「内部表征比外部文本更诚实」提供了工业级背书（呼应第 2 期 Cohere 事件：盯行动与激活，别盯自述）。(b) 对你做评估：「probe 只能检已知类」意味着部署面真正的兜底仍是输出审计+网络日志对账（L3）——分层里没有任何单层可信，这个架构结论可以直接搬进你自己的 harness。(c) 研究面值得跟进：监控用模型与被监控模型同源，「监控器的能力上限」会成为对齐工程的核心变量，作者自承 prompt 针对 Sol 调优——这条产品线（监控 agent 工程化）刚开了个头。

## 8. 工程与社区快讯（一句密度）

- **UNCUT**（[GitHub](https://github.com/Balanov/uncut)，837 行 Go 单文件 harness）：卖点是「lossless」——永不压缩/截断上下文、provider 截断输出直接报错不当成功、无 TUI 无遥测、四工具+stdin/stdout，OpenAI 兼容端点（含本地）。**对你的价值是反着读的**：当所有 harness 都在卷 context engineering，它把「全量、不丢、可复现」做成 7MB 的对照组——做 agent 实验时它是很好的 baseline 工具。
- **craft-anything**（[GitHub](https://github.com/storytold/craft-anything)，纯 Rust）：指一个网站/应用/游戏，agent 用真实检查工具研究原作→净室重建→对照原品迭代；**正好撞上 Anthropic 刚收紧的「复刻现有游戏」禁令**——这类「AI 逆向工程」工具与 ToS 的张力是新的法律灰区信号。
- **linux.do 社区实测**：(a) 「Ciallo 测试」分辨 ChatGPT 实际路由到 GPT-6-Luna（降智）还是 Astra——区分后台换模的民间指纹法，与第 7 条 6.2-Astra 灰度互为印证；(b) DS4.1F（大肥鱼）真实误删案例：路径引号转义错误致强制递归删错目录——又一条「shell 高危操作要人工 gate」的现场样本；(c) 实测槽点：DS4.1F 20 万上下文后丢死步骤；社区共识「Claude 指挥、GPT/Terra 干活」仍是主流分工。
- **卡兹克自动化系统**（公众号分享）：rules.json 事件驱动 agent、Mac Mini 执行、自建 CI 中台走「审查-检查-合并-发布-核实」五步、飞书卡片只管删数据/花钱/改方向三类拍板——**与 DeepSeek dsh-superagent 的「需要你」注意力队列同一设计哲学**：人只出现在不可逆决策点。民间复制成功说明该范式已工程收敛。

## 本地/小模型观察

本期无 2 万元内专用小模型的发布级跃迁，但有一个**比新模型更值钱的可复现手法**和一个工程跟进：

- **Weight-space programming 的本地含义**（见第 1 条）：被编辑的 Qwen3.5-0.8B 就在 HF，实验 8 的配方本质上是「前沿模型当诊断医生、小模型当被修器官」——定位缺陷方向→从 MLP 输出列减去→零训练提升。你完全可以在单张消费级卡上复现整条链（logs 仓有全部 prompt 与代码），甚至把「让 Astra/Opus 5.5 修你手里的 0.8B-9B 模型」变成自己的实验管线；这是目前**小模型可定向维修**的最具体公开证据。注意边界：只修得好「有单一可归因缺陷」的模型（循环方向），修不出没有的能力。
- **UNCUT**：本地模型适配友好（任意 OpenAI 兼容端点），「lossless 对照组」特性在测小模型真实上下文能力时尤其有用——排除 harness 压缩带来的测量噪音（memdoor 实验已经证明 fresh context 的影响有多大）。
- **过滤**：Ming-3.0-audio-tiny（9.3B/2.7B active）看似适合本地音频 agent，但实为 9/3 旧模型、下载量 <3k、无社区实测信号，不硬凑；Nanbeige4.3-33B 在 HF trending 但无实质评测，下期有信号再报；K3.1 Pro 权重若明天落地，MXFP4 ~1.5TB 级仍明确不在 2 万元圈。
