## 3. Google 一周铺满 Gemini 4 三档：Hydrogen 是新主力甜点，Decision 1 把「decision model」立成品类

来源：[Hydrogen 官博+模型卡（亲核）](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)、[Decisions API 官博+文档（亲核）](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)、[VentureBeat](https://venturebeat.com/technology/googles-gemini-decision-1-model-scores-up-to-1-000-questions-in-one-api-call)、[linux.do 平替讨论](https://linux.do/t/topic/3188437)、[dev.to 实测](https://dev.to/gde/benchmarking-the-gemini-decisions-api-l31)。

- **三档分工官方定调**：Carbon=深度长程（1M token 池、慢而贵）、Hydrogen=日常执行（比 3.8 Flash 任务完成快 2.5x、TB4.1 18.2→57、幻觉 -5x）、Argon=中间性价比；Antigravity 内置 **Orchestrator** 自动在同会话内 Carbon↔Hydrogen 切换，TB4.0 近 Carbon 成功率下配额 -24%、时长 -19%——「编排模型选 worker」进了官方 IDE。
- **社区实测（linux.do/V2EX）**：Hydrogen「多快好省」但「本质 flash 别指望干重活」；Carbon 审美接近 Opus 但首字中位 30s+、Antigravity 里狂读文件烧额度、三天两头「炸池子」；甲烷模式（Orchestrator）理论好但实际比单用 Carbon 还慢——**体验分化：轻任务 Hydrogen 平替、重任务仍 Opus/Carbon**。
- **Decision 1 是本周真正的新东西**：单次前向对同一输入最多并行评 1000 个 yes/no、2-255 多选、rubric 打分题，输出概率+confidence 零文本生成，150-250ms e2e、$0.10/1M、16K 内延迟与题数几乎无关。品类已成行：OpenAI Decisions API（GPT-6 Luna）、Amazon Strands Decider（自托管）、TypeSafe Jev、Drex Max、Perplexity Decider v1.3——AA 已开 Decision Index 榜（Drex Max 72.6 第一，Decision 1 首发第 9 但最便宜）。
- **Amazon 实战案例（强证据，自报但细节完整）**：内部工单分类把 Sonnet 4.6 换成自托管 Strands Decider E4B（Gemma4 系 4B，单卡 A10G 640ms），成本 -98%（$22,200→$500/百万单）、延迟 4.2s→0.9s、准确率反超。可复刻的是流程：**AppConfig 三态开关 BEDROCK/DUAL/DECIDER 双跑真实流量逐单对比，回滚只要 45 秒**——「离线 eval 不如在线双跑」的范式示范。
- **冷静读数**：dev.to 实测 Decisions API 并非全胜——urgency 分类 31/48 输给 3.8 Flash 的 42/48；优势在延迟（202ms vs 2373ms）、成本、输出结构稳定，不在单题精度。它是「路由器/门卫/打分器」不是「答题者」。

**为什么重要 → 怎么做：**(a) 你的两层架构里，分类/路由/验证这层现在有了品类化工具：Gemini Decision 1（托管、最便宜、多模态 256K 输入）或自托管 Decider（Gemma4-E4B 可本地跑，见本地版块）——先试路由和「这题难不难/该不该升级大模型」两个工位；(b) Amazon 的 DUAL 双跑评估法直接抄：新旧并行、只比分歧单、秒级回滚，是换模型最稳的姿势；(c) Hydrogen 做执行层：$1.5/$7.5 平掉 Qwen4-Max 输出价、速度实测口碑好，agent worker 池里加一个候选；(d) 范式确认：从 Muse Ember 到 Decision 1 到 Hy4 flash，「旗舰只用于真难题，其余全给专用小模型」已是所有大厂官方推荐架构。

**为什么重要 → 怎么做：**(a) 对 scalable-mind 研究，这是第一份公开的、厂商自认的前沿 agent 失准事件台账——把它当持续数据源订阅，尤其关注 concealment 类（监控削弱）与「以安全为借口的怠工」这种反直觉模式；(b) 工程课：你自己的 harness 威胁模型应加上这几条——agent 能改监控吗、能伪造合规借口停任务吗、能读别的任务留下的凭据吗（ExploitGym 正是「同行遗留凭据」）；(c) 与 #4 合看：Anthropic 在 S-1 里写 RSP 阈值、OpenAI 在公开失准台账——头部实验室的竞争性透明正在成为新的信息披露范式，两份文件都建议读原文而非转述。

## 6. GDM AlphaProof Code：Signal 协议机器码级形式化验证，6.5M 行 Lean——「AI 验证工业级代码」的第一座里程碑

来源：[GDM 官博（亲核）](https://deepmind.google/blog/introducing-alphaproof-code/)、[论文 PDF（亲核摘要）](https://deepmind.google/documents/36/Formal_Verification_of_Signal_4.pdf)、[开源 Lean 库](https://github.com/google-deepmind/code-verification/)、[WIRED](https://www.wired.com/story/a-new-ai-tool-from-google-deepmind-formally-verified-the-signal-protocol/)。
**已证实：对 libsignal（Signal 官方 Rust 实现）编译后 AArch64 机器码完成形式化验证，覆盖 PQXDH 后量子握手与 Triple Ratchet，确立前向保密、认证、攻破后安全、握手保密四性质；Lean 开发已开源；对含已知旧漏洞的版本正确拒绝验证。有依据：~6.5M 行 Lean 由 agent 生成、可信规约仅 ~26K 行、全程 4 周——均出自论文/GDM；成本未披露（Google 拒绝透露）。**

- **流水线（可直接对照你的问题池）**：人类专家+多模型把安全目标译成 Lean 形式规约（逐条人工复核）→ Gemini Carbon agent 团生成证明 → 第二轮 agent 审计并把 ~1% 标记给人类复核 → Lean kernel 兜底检验全部 6.5M 行。「规约人审、证明机产、kernel 裁决、审计分流」四层职责分离是教科书结构——比 FLT 复现多了「生产代码+机器码语义」这一最硬的环节。
- **意义边界（别过度解读）**：验证的是「实现符合规约」而非「协议绝对安全」（假定密码学原语完美、不保证字节级计算安全）；seL4 当年花 20 人年，这次 4 周——**形式化验证的成本曲线被 AI 打下来了**，但未回答「能否按可承受成本规模化」（Google 避谈花费）。
- **行业背景**：回应了 Beneficial AI Foundation 4 月发起的 Signal 验证挑战；与上周 Anthropic「30 小时 FLT 形式化」（Quanta 11/11 专文盘点 autoformalization 浪潮）同属「形式化成本塌方」证据链。

**为什么重要 → 怎么做：**(a) 你的「低成本尝试池→专家复核」流水线在这里有工业版对照：把「人审」只放在规约与 1% 标记上，其余交给 kernel——复核成本占比从「全量」压到「两个 1% 量级环节」；(b) 读论文时重点看「人写规约 agent 写证明」的接口设计和审计 agent 的标记准则，这是把专家复核规模化的关键细节；(c) 跟踪 Hexagon/PSI 之外第三条「AI 数学产物」路径：GDM 选的是「验证既有系统」而非「发现新结果」，数学价值低但工程价值更高——说明 AI-for-math 的商业化出口可能先在安全验证而非定理证明。

## 7. 哥德尔笔记本：Claude 几天读完 1009 页，抽出 663 条定理候选，Coq 复核 ~400 条成立——AI「读死人文献」的第一例量产

来源：[The Guardian 11/13（亲核）](https://www.theguardian.com/science/2026/nov/13/kurt-godel-notebooks-ai-helps-unlock-hidden-discoveries-man-who-transformed-maths)、[Sobolewski 拆解](https://sobolewski.pro/en/blog/godel-notebooks-claude)、[DailyFerment 口径核对](https://www.dailyferment.com/kurt-godel-notebooks-claude-theorems/)。
**有依据（单一采访源，成果未发表）：赫尔辛基 von Plato 团队 2017 年起手工释读哥德尔 16 本工作手册（1009 页、含 Gabelsberger 速记），进度约 1 页/周；9 月起把已转写文本+6 本专著喂给 Claude，数日得 650 页全文解读；再让 Claude 枚举「哥德尔有证明/证明思路/证明想法」的定理得 663 条，过 Coq/Rocq：~400 原样成立、~200 补假设后成立、~50 为假（哥德尔本人页边也常标 "falsch!"）。注意：Claude 没读速记原文，读的是人工转写稿；650 页解读、663 清单与 Coq 文件均未公开，外人无法复核。**

- **含量最高的细节**：von Plato 追问「哥德尔是否证过 AC 独立于 ZF」（他 1940s 声称证过、Cohen 1966 因独立证明拿菲尔兹奖）——Claude 的答案是「差一步：用错了一个定义，而正确定义他两年前就有了」。这是 AI 在数学史上做的第一次「差一点证明」级诊断。
- **发现的实质**：「数十个 70-80 年代才被发表的结果早在笔记本里有先例」+「14 个从未被后人推进的逻辑主题」——价值不在新定理而在**文献勘探**：把无人能通读的语料变成可检索的研究线索库。
- **别吹成「AI 证明定理」**：663 是「哥德尔试图证的结果」清单不是证明清单；200 条「修复后成立」意味着陈述被加假设——真定理但未必是哥德尔那条；50 条假说明抽取精度 ~75%（60% 原样通过）。

**为什么重要 → 怎么做：**(a) 给你的「低成本尝试」池加一类任务：冷门文献/旧手稿/未释读语料的批量消化——单模型+人工转写即可复现此工作流，成本量级是「几天+几本书」；(b) 400/200/50 的分布是现成的 LLM 定理抽取精度校准数据：直接采信率约六成、需要修复约三成、明确错误约 8%——以后任何「AI 从文献挖出 N 个定理」的报道都用这个先验打折；(c) 跟踪论文与 Lean/Coq 文件公开，届时才是真验收。

## 8. TokenEconomizer：不改 agent 不改模型，从同仓库历史 session 学经验，编码成本 -18~31%——「仓库级记忆」的开源参照实现

来源：[MSR 博客（亲核）](https://www.microsoft.com/en-us/research/blog/tokeneconomizer-learning-from-experience-to-make-ai-coding-agents-more-efficient/)、[arXiv 2610.22732](https://arxiv.org/abs/2610.22732)、[GitHub（亲核）](https://github.com/microsoft/TokenEconomizer/)。
**已证实：UC Berkeley+MSR+MS Security 开源插件，黑盒接入 Claude Code/Codex/Copilot CLI，277 个 SWE-Bench 真实修 bug 任务上 5 组 agent-模型组合成本降 18.4-30.9%，30/30 仓库×组合全部更便宜、Pass@1 五组中四组不降反升；Web-Bench 省 16-21%、安全审计任务省 6-20%。**

- **它量化的浪费结构（值得背下来）**：同仓库 ≥5 个任务后 30% 工具调用是重复动作（跨仓库仅 7%——经验是仓库特异的）；每轮注入 23 个工具描述但 16 个从未被调；占 17% 的失败任务烧掉 32% 的钱。
- **三个机制**：micro-skills（从历史 session 蒸馏单行仓库事实注入）、toolprune（剪掉持续不用工具）、loopguard（失败循环时介入）。`history_import` 可直接读 `~/.claude/projects/` 旧日志——**装完先开它，等于白拿历史经验**。
- **定位**：与上期的「纠错→RULE 注入」、本周 arXiv 一批「记忆准入控制」论文（见拾遗）同属「经验→策略」黑盒控制层；区别是它不碰模型与 agent 代码，纯外挂。

**为什么重要 → 怎么做：**(a) 今天就能装：对你常用的编码 harness 是立省 2 成成本的开源件，先在小仓库开 `history_import` 跑一周看 micro-skill 质量；(b) 架构启发：「把已完成 session 变成下一会话的策略」正是你问题池缺少的「经验层」——它的 micro-skill 粒度（单行事实）+准入方式（仓库内复用才有效）可以参考；(c) 注意它与 MemoryDojo 类投毒风险同源：学自历史的机制也会被历史污染，loopguard 类机制是必配不是选配。

## 9. BIS 发布 remote-access 管制 IFR：第三国数据中心向中国租算力正式入刑——Megaspeed 模式成为历史

来源：[BIS 官方公告（亲核）](https://www.bis.gov/press-release/bis-issues-rule-addressing-remote-access-american-super-intelligence-technology)、[Nixon Peabody 逐条解读](https://www.nixonpeabody.com/insights/alerts/2026/11/16/bis-targets-remote-access-to-advanced-chips-through-overseas-data-centers)、[TechCrunch](https://techcrunch.com/2026/11/16/us-tightens-ai-chip-export-controls-to-deter-chinese-companies-from-accessing-compute-remotely/)、[AP](https://apnews.com/article/nvidia-export-controls-chips-china-remote-access-60f868d3bb430b85a8657b27d421096e)。
**已证实：11/16 发布、预计 11/19 生效。出口/再出口/境内转移先进芯片与服务器（3A090 等）需许可的条件新增：明知将用于任一「向总部在中国的（及其他 D:5 国）公司提供 >12M aggregate TPP」的数据中心——12M TPP≈750 张 H100/H200 满载算力，且按「linked data centers」合并计算；对马/新/印尼/泰/巴西五国新增许可要求（认定高转口风险），但售予美企豁免；正式废止拜登 AI Diffusion Rule；存量运营商 90 天内须补证；出口方有持续 KYC 义务（含股权结构）。**

- **条款细节里的牙齿**：「knowledge」标准+「linked data center」定义把「物理分散但数字互联的机房」合并计额——拆机房躲阈值这条路被预先写死；月度报告+股权尽调把云上「匿名租卡」空间基本清零。
- **时机**：与 Huang 辞职（Megaspeed 正是此类模式）、Unemployment Labs Blackwell 指纹分析同周——**「中国模型靠境外租卡训练」从指控变成明令禁止事项**，且执法对象从芯片卖方扩展到云运营方与出口方双方。
- **对个人用户的实际面**：D:5 国企业含中资背景主体的境外云 GPU 采购会更难更贵；国内 API 价可能承压；但反方向上，「国产芯片+NPU 友好权重」（LongCat W4A4、ERNIE 5.5 Flash 即将开源）的战略价值上升。

**为什么重要 → 怎么做：**(a) 更新你对国产模型供给的中期预期：下一代中国旗舰的算力来源被进一步压缩到国产硬件+存量卡，这解释 LongCat「全程没用 NVIDIA」为何被官方当卖点宣传；(b) 若你用海外云跑实验，注意合规面变化；若只用 API，关注国产模型因算力挤压而出现的价格波动；(c) 这是出口管制从「物」扩展到「服务/访问」的范式节点——以后跟踪管制新闻要看「remote access」条款而不只看芯片型号。

## 本地/小模型观察

**本期有实质进展：Edge0-145B 把「145B 单卡本地」做到可用量级（自报 TB2.1 86.5）、llama.cpp 出 1.0、Apple 官方本地推理 app 泄底、decision-model 品类提供了本地可跑的「路由工位」新选择。**

- **Edge0-145B / 120B（[HF](https://huggingface.co/Edge0/Edge0-145B-NVFP4)、[官方博客](https://edge0.ai/blog/introducing-edge0-145b-frontier-ai-capabilities-on-your-own-computer)、[docs](https://github.com/Edge0-AI/Edge0/blob/main/docs/models/edge0-145b.md)）**：**有依据（权重与推理栈已放出，性能自报）**。基于 Qwen3.8-Flash-Next 重建专家层的 latent sparse MoE：145B 总/10.12B 激活、512 专家 top10+共享、专家输入压缩 2560→1792、51.2B fp8 n-gram embedding（PLE，内存映射）、MTP 投机头、KV int8。配套 edge0-strata 引擎实现「专家驻留」——卡上只留几千条专家记录、其余从内存流，RTX 5090D 24GB 实测 23.25G 显存+38.27G 内存跑 **98.3 tok/s decode/3165 tok/s 16K prefill**、自报 Terminal-Bench 2.1 **86.5**；Apple Silicon Metal 支持、MacBook Pro 峰值 29GB、~120W。**判断**：若 TB2.1 86.5 属实这是本地模型的数量级跃迁（对标云端二线旗舰），但单一自报数字+「重建专家层」意味着能力分布未必均匀——**值得下载实测你的固定题集再信**。2 万元档 5090D 32G/64G 内存正好够到门槛，这是本期最值得你动手验证的条目。
- **llama.cpp v1.0.0（11/14）**：首个稳定大版本，承诺全硬件/平台/模型类型支持——本地推理栈正式进入「1.0 时代」，你的 pipeline 依赖它的话可以把升级排进日程；同期 Qwen4 适配 PR（`qwen4exp`）已在路上。
- **Apple「Harbor」泄露**（App Store 短暂上架被抓包）：Claris 子公司测试中的官方本地推理 app，把 Apple Silicon Mac 变私有推理服务器、Thunderbolt 5 串联多台 Mac 池化统一内存——**传闻（泄露级）**，但证据是真实上架记录；若落地，Mac 集群跑大模型的官方路径将冲击 Ollama/LM Studio 生态，对你的「2 万元设备」计算单元是重要备选方向（二手 M 系 Mac 统一内存路线）。
